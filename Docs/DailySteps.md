# 하루 걸음수와 로컬 저장

## 사용자 동작

- 워치 홈에 오늘 자정부터의 걸음수를 표시한다. 새로 실행할 때 이전에 저장한 오늘 값을 먼저 표시하고 센서 조회 결과로 갱신한다.
- 앱 화면을 닫거나 워치가 잠든 동안에도 시스템이 수집한 걸음수는 복귀 시 조회한다. 앱 재실행·워치 재부팅 후에도 앱 컨테이너의 저장 기록을 복원한다.
- 자정에는 이전 날짜 기록을 유지하고 새 날짜를 시작한다. 새 센서 이벤트가 없어도 타이머/날짜 변경 알림으로 전환한다. 백그라운드에서 자정을 지난 경우 복귀 시 전환한다.
- 권한을 거부하거나 센서를 사용할 수 없어도 저장된 기록을 지우지 않는다. 저장 실패 시 화면의 측정값을 유지하고 오류를 알리며 후속 저장/백그라운드 전환에서 재시도한다.
- iPhone의 실제 기록 수신은 WatchConnectivity 단계에서 구현한다. 이번 단계의 기록은 워치 자체의 로컬 기록이다.

## 집계와 날짜 규칙

`StepDay`가 기기 시간대의 Gregorian 날짜 키 `yyyy-MM-dd`와 자정/다음 자정을 계산한다. 하루 길이를 86,400초로 고정하지 않아 DST의 23/25시간 날짜도 처리한다. 시간대 변경으로 같은 날짜의 자정 구간이 달라져도 센서 구독을 다시 시작한다.

`DailyStepTracker`는 다음 순서로 동작한다.

1. 오늘 로컬 기록을 읽어 즉시 화면에 반영한다.
2. CoreMotion 실시간 구독을 오늘 자정부터 시작하고, 오늘 자정~현재 구간을 별도 조회한다.
3. 저장값·실시간 합계·비동기 조회 합계는 `max`로 병합한다. 누적 합계를 다시 더하지 않는다. 중복 값은 다시 저장하지 않는다.
4. 화면 종료/백그라운드 전환에서 구독과 날짜 타이머를 중지하고 대기 중 저장을 마무리한다. 복귀 시 오늘 구간을 다시 조회한다.
5. 자정 또는 날짜/시간대 변경 시 이전 구독 세대를 무효화한다. 이전 날짜나 이전 실행의 늦은 콜백은 오늘 값에 반영하지 않는다.
6. 센서의 보관 기간 안에 완전히 포함되는 이전 최대 6일의 구간을 조회해 미저장/미완성 기록을 보정한다. 이 복구는 현재 날짜 구간별로 한 번 수행하며 실패한 경우 다음 시작 때 재시도한다.

CoreMotion은 시작 날짜부터의 누적 데이터를 제공하고, 앱이 정지되어 있는 동안에는 콜백 전달을 중단한다. 과거 조회는 최근 약 7일만 지원한다. 따라서 7일 이상 앱을 열지 않은 기간 중 센서 보관 범위 밖에 있고 로컬에도 저장되지 않은 날짜를 새로 복원할 수는 없다. 이미 저장한 기록은 계속 유지한다. [누적 업데이트](https://developer.apple.com/documentation/coremotion/cmpedometer/startupdates(from:withhandler:)), [과거 조회 범위](https://developer.apple.com/documentation/coremotion/cmpedometer/querypedometerdata(from:to:withhandler:)).

## 저장 형식과 경계

- 구현: `PetPetCore/Data/Local/FileStepHistoryRepository`.
- 위치: 워치 앱의 `Application Support/PetPet/step-history-v1.json`.
- 형식: `{ "version": 1, "records": { "2026-11-07": 1234 } }`.
- 하나의 actor 인스턴스가 읽기·쓰기를 직렬화한다. 같은 날짜의 낮은 값/늦은 쓰기는 높은 기록을 덮어쓰지 않는다. 파일은 `.atomic`으로 교체한다.
- 쓰기 실패 시 변경분을 메모리에 유지해 다음 저장에서 전체 기록을 다시 쓴다. 읽을 수 없는 JSON이나 알 수 없는 스키마 버전은 오류로 처리하고 기존 파일을 덮어쓰지 않는다.
- `record(for:)`는 날짜별 조회, `allRecords()`는 최신 날짜부터의 전체 조회를 제공한다. 서버 DTO·인증·보상·식사 횟수는 이 파일에 섞지 않는다.
- 첫 구조 정비 단계에는 영구 걸음 기록이 없었으므로 이전 데이터 마이그레이션은 필요하지 않다.

## 검증 시나리오

공용 패키지 테스트는 캐시 우선 표시, 앱 재실행, 자정 수동/자동 전환, 여러 날짜 후 복귀, 시간대/DST, 권한 거부, 지연·중복 콜백, 조회와 실시간 값의 역순 도착, 저장 실패 후 재시도, 최근 기록 복구, 7일 창 경계, 파일 재열기·동시 저장·손상/미지원 버전 보존을 확인한다.

```sh
swift test --package-path Packages/PetPetCore
```

실기기 수동 확인: 오늘 총 걸음수 표시 → 몇 걸음 걷기 → 화면을 닫았다 복귀 → 앱 종료·재실행 → 같은 날짜 합계가 유지·갱신되는지 확인한다. 센서 전달에는 지연이 있을 수 있다. 날짜 전환·시간대·DST는 주입한 시계와 달력으로 자동 테스트하며 실제 날짜를 바꿀 필요는 없다.

2026-11-07 검증: 공용 패키지 테스트 24개 통과, iPhone·watchOS Debug/Release 시뮬레이터 빌드 통과. 실제 Series 10(watchOS 26.6)에 설치·실행하고 앱 컨테이너에서 오늘을 포함한 날짜별 저장 파일의 스키마와 기록을 확인했다. 실기기 설치 시 Xcode 증분 업데이트의 placeholder 오류는 앱 삭제 없이 `devicectl device install app` 전체 업데이트로 해결했다.
