# 아이폰·워치 동기화

워치를 걸음수·펫 상태의 원본으로 두고, 아이폰은 수신한 상태를 읽기 전용으로 보여준다. 아이폰 센서 값을 더하거나, 아이폰의 빈 초기 상태로 워치 데이터를 덮어쓰지 않는다.

## 사용자 동작

- 워치에서 PetPet을 열고 걷기·먹이·성장 상태가 바뀌면 아이폰으로 최신 상태를 보낸다.
- 아이폰 홈은 오늘 걸음수, 펫 레벨·기분·경험치·스탯·호감도·마지막 식사, 보유 먹이를 표시한다.
- 마지막 수신값은 아이폰에 저장하므로 앱 재실행이나 연결 끊김 뒤에도 볼 수 있다. 마지막 동기화 시각과 연결 상태를 함께 표시한다.
- 아이폰의 **지금 동기화** 또는 아래로 당기기는 현재 워치에 최신 상태를 요청한다. 직접 연결할 수 없으면 저장된 기록을 유지하고 워치 앱을 열도록 안내한다.
- 오늘 날짜의 기록이 없으면 `—`를 표시한다. 어제 값을 오늘 값으로 표시하거나 없는 값을 0으로 만들지 않는다. 아이폰 날짜·시간대 변경과 앱 복귀 시 오늘 기록을 다시 선택한다.

## 전송과 저장

`PetPetConnectivity`는 Apple WatchConnectivity의 `WCSession`을 감싼 공용 플랫폼 어댑터다. Foundation 도메인·저장소·수신 순서 처리는 `PetPetCore`에 두며, SwiftUI·CoreMotion·WatchConnectivity에 의존하지 않는다.

1. 워치의 저장 완료된 펫과 걸음수 기록을 읽는다. 센서의 대기 중 저장도 먼저 완료하고, 저장 실패 시 보내지 않는다.
2. `WatchSnapshotPublisher`가 송신 작업 전체를 직렬화한다. 파일에 송신 원본 ID와 증가하는 순번을 먼저 저장한 뒤 전송한다. 늦은 송신 작업이 시스템의 최신 전송값을 덮어쓰는 것을 방지한다.
3. `updateApplicationContext`로 최신 상태를 예약한다. 직접 연결되면 `sendMessage`도 사용해 빠르게 전달한다. 두 경로로 중복 수신되어도 순번으로 한 번만 반영한다.
4. 아이폰은 버전·크기·날짜·수량·펫 수치를 검증하고 원자적으로 저장한다. 기존 수신 순번 이하의 데이터는 무시한다. 워치 시계가 뒤로 바뀌어도 순번 비교에는 영향을 주지 않는다.
5. 워치 재설치로 송신 ID가 바뀌면 새 상태를 받아들이고 이전 ID를 은퇴시킨다. 이후 이전 ID의 지연 데이터는 무시한다. 여러 워치 사이의 전환은 WCSession의 현재 워치 디렉터리 식별로 구분하며 이전 워치의 캐시를 현재 값으로 표시하지 않는다.

전송은 펫과 보유 먹이, 최신 날짜순 최대 7일 기록만 포함한다. 전체 걸음수 보관 파일을 줄이거나 지우지 않는다. 보상 지급 내역·터치 누적 카운터·인증 정보는 전송하지 않는다. JSON 페이로드를 60,000바이트 이하로 제한한다.

| 위치 | 파일 |
|---|---|
| 워치 원본 | `Application Support/PetPet/step-history-v1.json`, `pet-progress-v1.json` |
| 워치 송신 순번·최신 전송본 | `Application Support/PetPet/watch-sync-outbox-v1.json` |
| 아이폰 수신 캐시 | `Application Support/PetPet/watch-snapshot-v1.json` |

손상되었거나 알 수 없는 버전의 저장 파일은 덮어쓰지 않는다. 저장 실패는 다음 데이터 변경·재연결·수동 동기화 때 재시도한다. Debug 빌드만 `connectivity-debug.json`에 연결 플래그와 SDK 오류 코드를 기록하며 걸음수·펫 값·계정·기기 식별자는 넣지 않는다.

## Apple 플랫폼의 전달 시점

Application Context는 직접 연결되지 않아도 예약할 수 있지만 즉시 전달되는 통로는 아니다. 시스템이 적절한 시점에 마지막 상태를 전달한다. 아이폰의 직접 메시지는 실행 중이지 않은 워치 앱을 강제로 깨우지 않는다. 따라서 상시 실시간 수집·즉시 동기화를 보장하지 않으며, 최신 값이 필요할 때 워치 앱을 열도록 안내한다. 권한·로그인·서버 설정을 추가로 요구하지 않는다.

공식 근거: [Application Context](https://developer.apple.com/documentation/watchconnectivity/wcsession/updateapplicationcontext(_:)), [즉시 메시지와 깨우기 동작](https://developer.apple.com/documentation/watchconnectivity/wcsession/sendmessage(_:replyhandler:errorhandler:)), [워치별 디렉터리](https://developer.apple.com/documentation/watchconnectivity/wcsession/watchdirectoryurl).

## 검증

공용 패키지 55개 테스트는 기존 걸음수·성장 42개와 동기화 13개다. 송신 순번의 재실행 유지, 시계 되돌림, 동시·역순·중복 수신, 워치 재설치·대상 변경, 손상·저장 실패 후 재시도, 자정·시간대 변경, 전송 용량과 기록 개수 제한을 검증한다.

페어링한 시뮬레이터의 워치 컨테이너에 넣은 테스트 걸음수 4,321과 펫 상태가 WatchConnectivity를 거쳐 아이폰 화면에 표시되는 것을 확인했다. 실제 기기에 테스트 걸음수를 주입하지 않는다.

실기기 확인 항목: 양쪽 앱 실행 → 오늘 걸음수·펫 수신 → 워치에서 먹이 사용 후 갱신 → 아이폰 재실행 후 캐시 복원 → 워치 연결이 없을 때도 기존 기록 유지. 날짜 변경 뒤에는 새 날짜의 기록이 오기 전까지 어제 값이 오늘 칸에 나오지 않아야 한다.

2026-11-07 실기기 상태: 아이폰·Series 10에 설치 완료. 양쪽 WCSession 활성화와 상대 앱 설치 인식, 워치의 Application Context 예약을 확인했다. 양쪽 직접 연결은 `isReachable == false`이고 아이폰의 첫 수신은 아직 확인하지 못했다. 워치 앱이 열린 상태에서 실제 수신·갱신을 확인하는 항목은 남아 있다. Debug·Release 시뮬레이터 빌드와 양쪽 서명 빌드는 통과했다.
