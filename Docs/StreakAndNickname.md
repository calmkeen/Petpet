# 스트릭·닉네임

Android 기준은 `Chaeros/StepMate`의 `4e2b5e54902efd9630dc5fe7595ca0fb2656d0e3`, 서버 계약은 `Chaeros/StepMate_SpringBoot`의 `bcdcefbb226951785e09a82c30ab473ef77e39da`다. 운영 서버에 요청해서 검증한 결과가 아니라 해당 소스와 모의 응답을 기준으로 구현했다.

## 워치에서 사용하기

크라운 요약 페이지 순서는 **홈 → 성장 → 먹이 → 스트릭 → 계정과 백업**이다. 스트릭의 **월별 걸음 기록**을 열면 연속 일수, 월별 색상 기록, 날짜별 걸음수를 볼 수 있다. 이전·다음 달 버튼 또는 가운데 연·월 버튼으로 기간을 바꾼다. 연·월 선택은 watchOS 기본 Picker를 사용한다.

작은 캘린더 칸은 색상 확인용이며, 아래의 **날짜** 버튼을 열어 watchOS 기본 목록에서 날짜를 고른다. 크라운으로 목록을 스크롤할 수 있고, 선택한 날짜의 걸음수를 아래에 표시한다. 없는 날짜의 기록은 0걸음이다. 캘린더의 작은 칸 대신 날짜 목록을 사용하는 것은 워치의 터치 영역과 접근성을 위한 플랫폼 차이다. 이전·다음 달 버튼의 터치 영역은 각각 최소 44pt다.

상세 화면 아래에는 백업·보상 버튼과 닉네임 변경이 있다. **계정과 백업 → 백업 관리 → 닉네임 변경**으로도 같은 편집기를 연다. 시스템 입력 화면으로 입력한 뒤 중복 확인이 끝나면 **변경하기**가 활성화된다. 스트릭 조회에는 로그인이나 아이폰 연결이 필요하지 않다. 닉네임 확인·변경에는 로그인한 아이폰과의 직접 연결이 필요하다.

## Android와 같은 스트릭 규칙

| 항목 | 규칙 |
|---|---|
| 워치 연속 일수 | 오늘부터 거꾸로, 하루 1보 이상인 연속 날짜 수. 오늘이 없거나 0보면 0일 |
| 아이폰 연속 일수 | Android 폰과 같이 오늘 이하의 마지막 백업 기록일부터 거꾸로 계산. 화면에도 기준을 명시 |
| 워치 원본 | `StepHistoryRepository.allRecords()`의 전체 로컬 기록. 아이폰 표시용 7일 스냅샷을 사용하지 않음 |
| 아이폰 원본 | 로그인 계정의 `GET /api/v1/stepcounts/me`. 최근 365일 히트맵과 계정별 로컬 캐시 |
| 날짜 경계 | 현재 시간대의 Gregorian 달력. 월·연도·윤년·서머타임을 날짜 단위로 처리 |
| 7일 이상 | 불꽃 표시. 별도의 스트릭 보상은 추가하지 않음 |

월별 칸은 일요일부터 시작한다. 기본 목표 10,000보와 아래 구간은 Android와 같다.

| 걸음수 | 색상 |
|---|---|
| 0 | `#2E2E2E` |
| 1–2,999 | `#6C6C6C` |
| 3,000–5,999 | `#BBDEFB` |
| 6,000–9,999 | `#64B5F6` |
| 10,000 이상 | `#2196F3` |

워치는 조회 전에 대기 중 걸음수 저장을 완료하며 저장 실패를 표시한다. 기록 변경은 화면이 보이는 동안에만 잠시 모아 갱신한다. 센서 추적 수명은 기존 루트가 관리하므로 스트릭·닉네임 화면 이동이 추적을 중단하지 않는다. 아이폰은 백업 완료·계정 변경·앱 복귀 때 기록을 다시 조회하고 수동 새로고침도 제공한다. 백업 전의 새 기록이 아이폰 스트릭에 아직 나타나지 않는 것은 Android 폰과 같은 동작이다.

## 닉네임 API와 입력

| 동작 | 요청 |
|---|---|
| 현재 프로필 | `GET /api/v1/users/me` |
| 중복 검사 | `GET /api/v1/users/nickname/check?nickname=…` |
| 변경 | `PATCH /api/v1/users/nickname`, JSON `{"nickname":"…"}` |

기존 Bearer 인증·refresh 경로를 사용한다. 체크와 변경 응답은 `duplicated`, `nickname`, `message`를 받는다. 변경 응답도 HTTP 200이면서 `duplicated: true`일 수 있으므로 성공으로 취급하지 않는다. HTTP 409도 중복으로 안내한다. 요청과 서버가 반환한 닉네임이 정확히 같은지 검사한 뒤 저장한다.

Android의 Kotlin `String.length`와 맞춰 UTF-16 길이 2 이상을 요구한다. 공백만 입력하면 요청하지 않는다. 서버 DB의 기본 문자열 열 크기에 맞춘 255 UTF-16 단위 상한도 둔다. 앞뒤 공백·대소문자·Unicode 표현을 임의로 정규화하지 않는다. 현재 이름과 정확히 같으면 변경 버튼을 끈다. URL 쿼리의 `+`는 Spring 쿼리 디코더에서 공백으로 바뀌지 않도록 `%2B`로 전송한다.

입력 후 350ms 대기하고 검사한다. 입력이 바뀐 뒤 늦게 도착한 결과는 버리며, 사용 가능하다고 확인한 정확한 값만 제출한다. 중복과 통신 실패를 구분하고 재시도를 제공한다. 프로필 조회·닉네임 변경·refresh가 겹쳐도 최신 닉네임과 회전된 토큰을 서로 덮어쓰지 않도록 저장을 직렬화한다. 로그아웃·계정 변경 중인 이전 응답은 거절한다.

워치는 계정 ID·요청 ID·작업·닉네임만 담은 환경별 메시지를 아이폰에 보낸다. 아이폰의 `PhoneProfileCoordinator`가 같은 `BackendClient`를 사용해 처리하며 토큰을 워치로 보내지 않는다. 응답의 ID·계정·Debug/Release 환경과 워치의 현재 계정을 확인한다. 닉네임 변경은 백그라운드 대기열에 넣지 않으므로 연결이 끊긴 뒤 뒤늦게 적용되지 않는다. 완료하면 아이폰 Keychain 표시 정보와 워치 계정 캐시를 갱신한다.

기존 서버의 위 3개 프로필 경로를 사용하므로 닉네임·스트릭 자체를 위한 새 서버 API는 필요하지 않다. Release의 Apple 로그인 서버 작업은 별도 [서버 변경 명세](AppleSignInServer.md)를 따른다.

## Debug 모의 계정으로 테스트

1. 두 앱의 Debug 버전을 열고 아이폰에서 **개발용 계정으로 로그인**한다. 기존 모의 로그인 상태도 그대로 유지한다.
2. 워치의 **스트릭 → 월별 걸음 기록**에서 현재 월·다른 월·날짜 목록을 확인한다. 오늘 0보면 스트릭은 0일이다. 테스트를 위해 실제 워치에 임의 걸음수를 넣지 않는다.
3. **닉네임 변경**에서 한 글자는 변경 불가, `사용중닉네임` 또는 `StepMate`는 중복 안내가 나오는지 확인한다. 두 이름은 모의 서버에만 예약된 테스트 값이다.
4. 다른 2자 이상 이름을 입력해 변경한다. 아이폰과 워치 표시, 앱 재실행 뒤 유지 여부를 확인한다. 모의 현재 이름도 중복 검사에서 사용 중으로 반환한다.
5. 워치 기록을 모의 백업하고 아이폰 홈의 스트릭을 새로고침한다. 워치 기록은 백업 후 아이폰 히트맵에 반영된다.
6. 아이폰과 연결할 수 없으면 워치 편집기가 실패·재시도를 안내한다. 로컬 스트릭·먹이·성장 기능은 계속 사용할 수 있다.

모의 서버의 닉네임은 기존 `Development/mock-backend-v1.json`에 선택 필드로 추가한다. 이전 파일도 읽을 수 있고 로그인·refresh·앱 재실행 후 유지한다. 아이폰 히트맵 캐시는 `Development/server-streak-v1.json`이며 계정 ID가 다른 캐시는 표시하지 않는다. Release의 기존 파일과 Keychain 공간은 그대로 분리한다.
