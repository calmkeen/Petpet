# Android 기능 대응표

기준 저장소: [Chaeros/StepMate](https://github.com/Chaeros/StepMate)

2026-11-12 후속 요청으로 실제 홈 재생과 닉네임 경로를 다시 검사했다. 홈의 캐릭터를 입력 대기 버튼 밖으로 분리하고 프레임 보간을 추가했으며, 실제 홈에서 2→16개 프레임 사용을 확인했다. 중간 터치 횟수는 숨기고 스트릭에 닉네임 바로가기를 추가했다. 공용 183개·워치 모델 10개·native UI 5개와 Debug/Release 시뮬레이터 빌드, 폰 모의 닉네임 저장 일치를 확인했다. 운영 연동·워치 단독 서버 요청의 남은 차이까지 [홈·닉네임 재점검](MotionAndNicknameAudit-2026-11-12.md)에 구분했다.

2026-11-12에는 **UI 구성**을 별도로 비교했다. 공유 Figma와 Android 홈·메인 이동 코드를 기준으로 워치 홈의 성장·먹이 바로가기를 제거하고 중앙 펫과 전체 배경을 복원했다. 메인은 홈·상태·게임·스트릭·음성의 5개 페이지로 묶는다. 이전 기능 대응 검토를 화면 구성까지 완전히 같다는 의미로 해석하지 않는다. 세부 변경과 watchOS의 시계·크라운·입력 차이는 [워치 홈 구성 검토](WatchHomeParity-2026-11-12.md)를 따른다.

분석 기준: `main`, 커밋 `4e2b5e54902efd9630dc5fe7595ca0fb2656d0e3`. 아래 Android 항목은 소스에 구현된 경로를 기준으로 하며, 서버의 실제 운영 결과를 검증했다는 의미는 아니다.

게임·랭킹·음성 규칙과 Debug/운영 API·검증 범위는 [게임과 대화](GamesAndChat.md)를 따른다. 주요 클라이언트 기능은 구현했으며 운영 Apple 인증·서버 연동은 설정 후 검증해야 한다.

2026-11-09 [최종 전체 대응 검토](FinalAndroidAudit-2026-11-09.md)에서 GitHub의 현재 `main`이 같은 기준 커밋임을 다시 확인했다. 워치의 백업 대기 중 로그아웃, 빠른 복귀의 기분 갱신 중복, 전경 활동 시각 갱신 누락을 수정하고 슈팅 콤보 표시와 체력 0 즉시 종료를 보완했다. 공용 180개·워치 모델 16개 회귀와 Debug/Release 시뮬레이터 빌드가 통과했다. 최종 네이티브 흐름과 상태 대조 결과는 해당 검토 문서를 따른다.

2026-11-08 [워치 중심 전체 검토](WatchAudit-2026-11-08.md)에서 같은 Android HEAD와 다시 비교했다. 반복 채팅·취소 경합, 센서 재시도, 큰 게임 능력치·계정별 랭킹, 네이티브 SSE, 인증 만료 전파, 40mm 배치·날짜 선택을 보완했다. 공용 169개 테스트와 Debug/Release 시뮬레이터 빌드를 통과했다. 후속 XCTest로 40mm의 날짜·연월 복귀와 두 게임도 확인했으며 시작 화면 잘림·복귀 후 일시정지 시작을 수정했다. 검증 범위와 화면은 해당 문서에 기록했다.

## 호환 기준

2026-11-08 [아이폰 앱·동기화 검토](PhoneAudit-2026-11-08.md)에서 Android mobile과 다시 비교했다. 서버 펫 표시·워치 설치 안내를 보완하고, 조회 오류·인증 만료·날짜 갱신·채팅 취소·워치 전환과 Debug/Release 표시 데이터 혼합을 수정했다. Android 하단 순위·AI·내 정보 버튼은 실제 소스에서 자리 표시자였으며 iOS의 기존 실제 기능을 유지했다.

- 앱 이름·Xcode 타깃·Bundle ID는 PetPet의 기존 값을 사용한다. Android 패키지 이름을 Apple Bundle ID로 복사하지 않는다.
- iOS 18 / watchOS 11 최소 버전을 유지한다. 구조 정비를 위해 사용자 기기나 Xcode 버전 업그레이드를 요구하지 않는다.
- Android의 `Long` 식별자·능력치는 공용 모델에서 `Int64`로 다룬다. `PetStatistic` ID 1~6, `PetMood`의 HAPPY/SAD/HUNGRY 값은 원본 의미를 유지한다.
- iOS는 Apple, Android는 Google을 사용한다. 같은 내부 계정으로 연결하려면 서버가 두 제공자를 지원하고 명시적인 계정 연결 절차를 제공해야 한다. Apple 신규 로그인을 기존 Google 계정에 이메일로 자동 연결하지 않는다. [서버 변경 명세](AppleSignInServer.md). Apple 서버 키와 Android 비밀 값은 iOS 소스에 복사하지 않는다.
- Google Credential Manager, Wearable Data Layer, Room, Samsung Health SDK, Android 음성 입력 UI는 Apple에서 직접 사용할 수 없다. 해당 기능은 Apple용 어댑터와 UI로 구현한다.
- 실제 규칙은 README나 화면 이름보다 위 기준 커밋의 코드가 우선한다. 원본 버그까지 동등하게 재현하지 않으며, 의도된 규칙과 버그가 갈리는 경우 이 대응표에 결정과 차이를 남긴다.

## 하루 걸음수의 플랫폼 차이

Android의 부팅 이후 센서 원시 누적값·offset 보정은 Apple에 복사하지 않는다. CoreMotion은 요청한 시작 날짜부터의 누적 합계를 제공하므로 자정 구간 조회와 실시간 값을 최댓값으로 병합한다. 재실행·센서 재연결 시 중복 합산을 방지하고, 저장된 오늘 기록보다 작은 일시적인 응답은 기록을 줄이지 않는다.

날짜별 저장·앱 재실행 복구·자정 초기화는 같은 사용자 동작을 제공한다. 백그라운드에서는 앱의 지속 실행을 가정하지 않고 복귀 시 시스템 기록으로 보정한다. CoreMotion의 과거 조회 한계는 최근 약 7일이며, 기존 로컬 기록은 이 범위 이후에도 유지한다. [자세한 구현·검증 기준](DailySteps.md).

## 먹이·성장과 보상의 차이

게임 수치와 지급량, 서버 백업 성공 뒤 지급하는 시점은 Android와 동일하다. Apple은 iPhone이 서버 요청을 수행하고 워치에 성공 확인을 보내므로 전달이 지연될 수 있다. 자정 뒤에 도착해도 원래 백업한 날짜의 기록에만 지급한다. 펫·먹이·지급 내역은 하나의 원자적 파일 저장으로 처리한다. 공복과 미접속이 동시에 성립하면 HUNGRY를 우선한다. 자세한 규칙은 [먹이·성장·보상](FeedingAndGrowth.md), 서버 계약과 설정·검증 범위는 [계정·백업·복원](AccountAndBackup.md)을 따른다.

## 스트릭·닉네임의 플랫폼 차이

워치는 오늘 기준의 전체 로컬 기록, 아이폰은 마지막 백업 기록일 기준의 서버 기록을 사용한다. 이 기준 차이는 Android의 워치·폰 코드에도 있다. 연속 일수는 하루 1보 이상이며 10,000보 목표 달성과 별개다. watchOS는 작은 달력 칸 대신 전체 크기의 날짜 선택 목록과 크라운을 사용하고 선택 후 이전 화면으로 돌아간다. 닉네임은 기존 서버 계약을 사용하고 아이폰이 인증을 담당한다. 입력 검증·API·모의 테스트와 실기기 확인 범위는 [스트릭·닉네임](StreakAndNickname.md)을 따른다.

## 워치 단독 연결 (2026-11-12)

워치 자체 로그인과 닉네임·백업/복원·랭킹·AI 요청 경로를 추가했다. Android의 워치 서버 호출처럼 iPhone 중계 없이 동작한다. Debug는 워치 내부 모의 서버, Release는 네이티브 Apple 로그인·워치 Keychain·HTTPS를 사용한다. Google 인증을 재사용하지 않으므로 운영 Apple API와 watch bundle audience 설정은 서버 작업으로 남는다. [구현·검증 범위](WatchStandalone-2026-11-12.md).

## 추가 Swagger API 연결 (2026-11-13)

누적 걸음수 랭킹, 슈팅·별계단 구간 랭킹, 대표 이미지 변경을 공용 BackendClient와 워치 UI에 연결했다. 단독/중계 모드와 Debug 모의 서버를 지원한다. [검증 범위와 운영 서버 경계](CommunityAPIs-2026-11-13.md).
