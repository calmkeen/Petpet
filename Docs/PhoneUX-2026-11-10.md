# 작은 아이폰 UI/UX 정리

## 변경 내용

- 워치와 같은 청록색 강조색, 둥근 카드와 버튼을 아이폰에 적용했다. 밝은 모드에서는 흰 글자와 대비되는 짙은 청록색을 쓰고, 어두운 모드에서는 강조 글자를 밝게 표시한다.
- 홈에서 연결 상태·동기화 버튼·오늘 걸음수를 먼저 확인한다. 펫과 성장 상태, 먹이, 스트릭을 카드로 정리했다. 큰 글씨에서는 바로가기·펫·능력치·먹이를 세로로 배치하고 긴 이름과 수치를 줄바꿈한다.
- 오늘 걸음 기록이 아직 없으면 `—`와 워치 앱을 열라는 안내를 함께 표시한다. 기록이 없는 상태를 0걸음으로 바꾸지 않는다.
- 계정 화면의 기본 작업을 개발용 안내보다 먼저 배치했다. 백업 버튼은 보상이 포함됨을 명시하고, 복원 미리보기에서는 능력치를 개별 행으로 보여 준다. 실제 백업·복원 조건은 유지했다.
- 닉네임 입력과 질문 작성, 복원 취소의 도구막대 버튼을 44×44pt로 키웠다. 주요 작업 버튼은 최소 48pt이고 큰 글씨에 따라 높이가 늘어난다.
- 랭킹과 대화를 화면 상단의 고정 선택 버튼으로 구분했다. 랭킹의 긴 닉네임·점수는 줄바꿈하고 게임 선택기를 전체 너비로 배치했다.
- 질문은 별도 작성창에서 편집한다. 2,000자를 넘으면 완료를 비활성화하고, 취소하면 이전 질문을 보존한다. 계정을 바꾸면 작성 중인 내용을 비우고 작성창을 닫는다. 로그인 전에는 필요한 안내와 비활성 상태를 표시한다.
- AI 응답 중에는 중단 버튼이 답변 앞에 나타나고 화면 중앙으로 이동한다. 긴 질문과 답변이 있어도 중단 버튼을 스크롤 없이 누를 수 있다.
- 스트릭 범례를 두 줄로 정리하고, 열지도 칸과 글자를 시스템 글자 크기에 맞춘다. 워치 연결 도움말의 개발자용 Xcode 설명은 Debug에서만 보인다.

## 검증 환경과 범위

실제 기기는 사용하지 않았다. 주 화면에서 창을 옮기거나 마우스를 조작하지 않고 CLI와 XCTest로 검사했다.

- Xcode 27.2 (27B52)
- 작은 화면: iPhone SE 3세대, 375×667pt / 캡처 750×1334px
- 동기화 페어: iOS 18.0 + Apple Watch SE 2세대 40mm / watchOS 11.0
- 추가 빈 상태·키보드 검사: 별도 iPhone SE 3세대 / iOS 27.2, 워치 미페어링
- 기본 글자와 시스템 `accessibility-extra-large`, 밝은 모드와 어두운 모드

큰 글씨 검사는 실제 시뮬레이터 시스템 설정을 바꿔 실행하고 매번 원복했다. 루트 SwiftUI 환경값만 바꾸면 별도 시트에 글자 크기가 전달되지 않는 경우가 있어, 복원창 버튼 높이와 질문 작성창 글자 높이도 검사했다. Debug의 화면 검사용 실행 인자는 Release에 포함되지 않는다.

키보드는 iOS 27.2에서 실제 화면에 표시된 영역을 기준으로 검사했다. 375×667pt 화면에서 키보드의 시작 위치는 y=451pt, 입력창은 y=114pt·높이 217.5pt였고, 취소·완료 버튼은 각각 44×44pt였다. 실제 문자를 입력한 뒤 초안을 취소하고 전용 미페어링 시뮬레이터를 로그아웃 상태로 돌려놓았다. iOS 18.0에서는 키보드 접근성 객체가 화면 밖에 있어 이 환경의 실행을 키보드 겹침 검증으로 세지 않았다.

| 검사 | 테스트 수 | 확인 내용 |
| --- | ---: | --- |
| 홈 | 4 | 기본·큰 글씨 × 밝은·어두운 모드, 걸음·성장·먹이·스트릭과 주요 버튼 |
| 상세 | 3 | 워치 안내, 계정, 닉네임 입력, 복원 미리보기·취소 |
| 랭킹 | 2 | 두 게임 전환, 내 이름·점수, 새로고침, 대화 전환 |
| 질문 편집 | 1 | 2,001자 제한, 완료 비활성, 취소 시 질문 보존 |
| AI 대화 | 2 | 기본·큰 글씨에서 반복 전송, 긴 질문, 자동 중단 버튼 표시·취소 |
| 재로그인·동기화 | 1 | 로그아웃 안내, 개발 계정 재로그인, 워치 기록 재표시 |
| 워치 없는 상태 | 1 | 최신 iOS에서 연결 도움말, 로그인·백업·복원 상태 |
| 소프트웨어 키보드 | 1 | 최신 iOS에서 큰 글씨·다크 모드 입력창, 글자 수, 취소·완료 버튼의 실제 표시 영역 |

채택한 위 15개 XCTest는 각각 성공 1건, 실패·건너뛰기 0건이다. 테스트별 결과, 제어 영역 측정값, 빌드와 최종 데이터는 [검증 JSON](Verification/PhoneUXSimulator-2026-11-10.json)에 기록했다. 이 작업에서는 먹이기·보상 수령·실제 복원을 실행하지 않고 화면과 복원 취소를 확인했다.

주요 제어 영역을 77회 측정해 최소 44pt와 화면 내 배치를 확인했고, 51장의 캡처를 남겼다. Debug 테스트 빌드와 아이폰·포함된 워치 앱의 Release 시뮬레이터 빌드도 통과했다. 기존 연결 패키지의 Swift 6 액터 격리 경고와 AppIntents 메타데이터 추출 안내는 남아 있으며 이번 UI 변경 범위에 포함하지 않았다.

## 검사 중 수정한 문제

- 공통 스타일 밖에 최소 프레임만 둔 도구막대 버튼은 실제 접근성 영역이 44pt보다 작았다. 버튼 스타일 내부에서 44×44pt를 지정한 뒤 다시 측정했다.
- 큰 글씨에서 가로 능력치와 먹이 행, 랭킹 이름이 좁아지는 문제를 세로 배치·줄바꿈으로 해결했다.
- 대화 작성창에서 취소해도 미완성 질문이 바로 반영되던 흐름을 별도 초안으로 분리했다. 계정 전환 시 초안도 지운다.
- 응답 상태를 표시하자마자 검사기가 스크롤하면 앱의 자동 스크롤과 충돌했다. 자동 이동 완료를 기다려 중단 버튼 전체가 보이는지 검사하도록 수정했다. 화면보다 긴 답변은 자연스럽게 스크롤할 수 있는지를 검사한다.

## 데이터와 설정 보존

UI 검사 후 저장 파일과 아이폰 수신 스냅샷을 비교했다. 펫 레벨 2·경험치 2·공격 50·방어 0·체력 9·포인트 0, 우유 2개·사과 2개와 기존 걸음 기록 3일이 유지됐다. 기존 백업 ID 집합 5개·복원 ID 집합 1개도 같고 대기 백업은 0개다. 모의 계정 닉네임 `FinalWatch217069`이 아이폰과 워치에서 일치하며, 펫·먹이·걸음 수신 스냅샷도 워치와 같다.

체력·걸음수 테스트 데이터를 주입하지 않았다. 검사에 사용한 두 아이폰의 글자 크기와 Simulator 키보드 설정은 원래 값으로 복원했다.

## 재실행

기존 백업이 있는 Debug 모의 계정과 전용 시뮬레이터 페어를 사용한다. 마지막 빈 상태·키보드 검사를 위해 별도 미페어링 iOS 27.2 아이폰을 지정할 수 있다. 실행기는 대상이 시뮬레이터인지 확인하고, 실패한 재실행에 이전 성공 기록이 남지 않도록 단계별 결과를 먼저 지운다.

```sh
python3 -B Scripts/test_phone_ux.py \
  --phone 96462AE4-4876-4635-A70E-EE0DBC2FCA05 \
  --watch 23172719-AC2C-4DAD-8FEB-8808093BD761 \
  --unpaired-phone E18E7FF8-2121-4EE4-9F0F-1ECFAFC1FD1B \
  --build /private/tmp/petpet-watch-ux-272 \
  --artifacts /private/tmp/petpet-phone-ux
```

작업 커밋은 `799e0ba`(공통 디자인·배치), `b5acaa9`(로그인 안내·질문 초안 분리), `fb5c0cc`(시뮬레이터 UI 검사)로 나눴다.
