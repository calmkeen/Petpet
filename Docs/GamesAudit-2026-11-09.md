# 게임·랭킹·AI Debug 전체 흐름 검토

2026-11-09, `codex/watch-pet-progression`에서 검토했다. iPhone SE 3 / iOS 18.0과 Apple Watch SE 2 **40mm / watchOS 11.0**의 전용 시뮬레이터 페어를 사용했다. 게임 점수나 AI 질문을 앱 저장 파일에 주입하지 않고 XCTest로 실제 게임·시스템 텍스트 입력·버튼을 조작했다. 검토 중 모델 회귀 재현은 Series 11 46mm / watchOS 26.5에서도 실행했다.

실제 기기 설치·실행, Mac 화면·마우스 조작, 운영 Apple 로그인·랭킹·AI 서버 요청은 하지 않았다. AI 답변과 계정은 Debug의 영구 모의 백엔드를 사용했다. 실제 마이크 음성 인식의 품질은 검증 범위에 포함하지 않았다.

## 수정

### AI 완료 후 입력 잠금

워치가 완료·오류 응답을 받았어도 아이폰의 작업 정리 응답을 기다리는 동안 질문 입력이 계속 잠겼다. 정리 응답이 지연되는 테스트로 완료·오류·다음 질문과의 경합을 재현했다.

완료된 작업의 입력 잠금을 먼저 해제하고, 해당 작업 ID로 후속 정리를 요청하도록 바꿨다. 늦은 정리 응답은 새 질문의 진행 상태를 변경할 수 없다. `734f743`.

### 40mm 랭킹 새로고침

기존 자동 toolbar 버튼은 40mm/watchOS 11의 랭킹 화면 접근성 계층에서 BackButton만 남아 실제로 사용할 수 없었다. 새로고침을 랭킹 목록 안의 명시적인 버튼으로 옮겼다. 최초 로딩 중에는 비활성화되고, 읽기 실패 후에도 다시 요청할 수 있다. 실제 별계단 결과 제출 → 독립 랭킹 진입 → 새로고침 → 내 기록 확인으로 검증했다. `cebe815`.

### 게임 결과의 계정 소유권

계정 A에서 끝낸 게임 결과를 화면에 둔 채 계정 B로 바꾸고 재시도하면 A의 점수가 B로 제출됐다. 두 watchOS 런타임의 모델 테스트에서 요청 수가 1회 대신 2회가 되어 재현됐다.

게임이 끝날 때 로그인한 계정을 기억하고, 다른 계정으로 바뀌면 해당 결과의 재전송을 막는다. 결과·로컬 최고 기록은 유지하며 새 게임을 안내한다. 로그인하지 않고 새로 플레이한 결과는 로그인 후 사용자가 재시도할 수 있다. `ee249fe`.

### 아이폰의 긴 질문 취소 후 빈 영역

긴 질문을 입력해 AI 응답을 중단하면 List의 입력 행이 579.5pt로 남아 화면 대부분을 빈 공간으로 차지했다. 목록 행의 크기 검사와 실제 화면으로 재현했다.

질문은 별도 편집 화면의 스크롤 가능한 입력창에서 작성하고, 목록에는 최대 세 줄의 미리보기만 표시한다. 목록 안의 편집기가 전체 텍스트 길이로 행 높이를 늘리는 경로를 제거했다. 같은 질문을 취소한 뒤 미리보기 행은 **109.5pt**였고, 반복 전송·중단·미리보기 크기 검사와 기존 대화 진입·홈 복귀 UI 회귀가 통과했다.

## 재실행

두 앱이 설치·실행되어 있고 피트니스 권한을 허용한 전용 시뮬레이터 페어를 사용한다. 이전 모의 계정의 로컬/서버 최고 기록이 일치하는 페어가 전제다. 실제 사용자 기기나 데이터를 초기화하지 않는다.

```sh
python3 -B Scripts/test_games_flow.py \
  --phone 96462AE4-4876-4635-A70E-EE0DBC2FCA05 \
  --watch 23172719-AC2C-4DAD-8FEB-8808093BD761 \
  --build /private/tmp/petpet-flow-build \
  --artifacts /private/tmp/petpet-games-new-run
```

13단계로 로그인 → 슈팅·다시 하기·최고 기록 → 별계단·랭킹 → 새로고침 → 아이폰 양쪽 랭킹 → 워치 AI 6회 → 중단·화면 복귀 → 로그아웃 → 로컬 게임·AI 로그인 안내 → 재로그인 → 랭킹·AI 재사용 → 아이폰 AI 반복·중단을 검사한다. 각 단계 후 펫 능력치·먹이 보존, 로컬 최고 점수 비감소, 서버 점수 일치, 워치 계정 전파를 파일로 대조한다. 기록하는 결과 JSON에는 인증 토큰을 포함하지 않는다.

중단된 검사는 같은 `--artifacts`에 `--skip-build --from-stage N`으로 이어서 실행한다. 스크립트는 시뮬레이터 UDID만 허용하고, XCTest 결과 번들에서 실제 1개 테스트의 통과를 확인한다.

시뮬레이터 특성에 맞춰 다음을 처리한다.

- Xcode가 상대 앱을 재설치해 저장 컨테이너가 이동하면, 설치 완료 후 상대 앱을 재실행하고 현재 컨테이너에서 결과를 읽는다.
- 40mm의 시스템 입력은 자동으로 받아쓰기를 시작하므로 해당 세션을 중단한 뒤 XCTest 키 입력을 넣고, ‘완료’가 활성화된 것을 확인한다. 선택적인 Siri 오디오 공유는 동의하지 않는다.
- 랭킹 첫 응답으로 목록 길이가 바뀐 다음 버튼을 찾아야 하므로, 내 랭킹이 로딩된 후 새로고침 항목으로 스크롤한다.
- 지연 생성되는 List 행의 상하 위치를 구분해 스크롤하고, 시스템 입력은 TextField 또는 Button으로 표현될 수 있어 접근성 ID로 찾는다.

## 자동 회귀

- PetPetCore 공용 테스트 **179개** 통과.
- 워치 대화·랭킹 모델 테스트 **7개** 통과: AI 완료/오류의 입력 해제, 이전 작업 정리 경합, 랭킹 실패·재시도, 계정 변경·이전 기록 보호, 로그아웃 AI 차단, 다른 계정 결과 재전송 차단.
- 최종 수정을 포함한 Debug·Release iOS/watchOS 시뮬레이터 빌드 통과.

## 전체 흐름 결과

네이티브 **13단계 모두 통과**했다. 각 XCTest 결과 번들에서도 단계마다 실제 1개 테스트가 통과한 것을 확인했다. 아이폰 입력 수정 후 기존 `PhoneAuditUITests.testConnectionGuideAndExtrasReturnHome`도 추가로 통과했다.

| 단계 | 확인한 흐름 |
|---|---|
| 0 | 아이폰 Debug 모의 계정 로그인 |
| 1 | 워치 슈팅 이동·일시정지·종료·다시 하기·재실행 후 최고 기록 |
| 2 | 별계단 정답·일시정지·시간 초과·점수 전송·랭킹 재조회 |
| 3 | 40mm 독립 랭킹 새로고침 |
| 4 | 아이폰에서 두 게임의 워치 제출 기록 조회 |
| 5 | 워치 시스템 입력 → AI 답변 완료를 같은 화면에서 6회 반복 |
| 6 | 긴 질문의 응답 중단·입력 재활성화·화면 복귀 후 초기화 |
| 7 | 아이폰 로그아웃 → 워치 계정 해제 |
| 8 | 로그아웃 상태의 로컬 게임 저장·AI 로그인 안내·원격 랭킹 미표시 |
| 9 | 같은 모의 계정 재로그인 → 워치 전파 |
| 10 | 워치 랭킹 복구·새로고침 |
| 11 | 재로그인 후 워치 AI 6회 반복 완료 |
| 12 | 아이폰 AI 2회 완료·긴 질문 중단·입력 행 높이 검증 |

전 단계에서 펫 **Lv.2 · 경험치 1 · 공격력 50 · 방어력 0 · 체력 9 · 남은 능력치 0**, 우유 **3개**·사과 **1개**가 유지됐다. 최종 워치 최고 기록과 모의 서버 최고 점수는 슈팅 **5점**, 별계단 **1계단/콤보 1**로 일치했다. 슈팅의 로컬 최대 콤보는 별도의 최고값 3으로 유지된다.
