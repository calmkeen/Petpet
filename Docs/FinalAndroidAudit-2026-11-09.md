# Android 대응 최종 검토 — 2026-11-09

GitHub 연결을 통해 Android `Chaeros/StepMate`의 현재 `main`을 다시 확인했다. HEAD는 **`4e2b5e54902efd9630dc5fe7595ca0fb2656d0e3`**으로 이전 검토 기준과 같다. 기존 비교 기록에 더해 실제 Kotlin 규칙과 Swift의 현재 코드·실행 경로를 재검토했다.

워치를 중심으로 **시뮬레이터만** 사용했다. 주요 네이티브 검증 대상은 Apple Watch SE 2 **40mm / watchOS 11.0**, 상대 앱은 iPhone SE 3 / iOS 18.0이다. Mac 화면 좌표나 마우스·창 이동을 사용하지 않았고, 실기기에 빌드·설치·실행하지 않았다.

검토한 Android 기준의 주요 클라이언트 기능에 대응하는 구현은 있다. 이번에 발견한 표시 누락은 슈팅의 현재 콤보이며 아래와 같이 보완했다. 플랫폼별 의도적인 차이는 유지한다.

- Google 로그인은 Apple 로그인으로, Wear Data Layer는 WatchConnectivity로 대응한다. 실제 서버는 Apple 제공자를 지원해야 한다.
- Android의 부팅 누적 센서 보정은 CoreMotion의 날짜 구간 합계로 대응하며 두 기기의 센서 값을 더하지 않는다.
- 좌우 페이지 전환은 크라운 세로 페이지로, 작은 달력의 날짜 터치는 선택 목록으로 대응한다.
- 복원 확인·실행은 기존 설계대로 아이폰에서 수행하고 워치에 적용한다. 워치에서 별도의 서버 자격 증명을 보관하지 않는다.
- Debug의 계정·백업·랭킹·AI는 모의 백엔드이며 운영 서버로 우회하지 않는다.

## 수정한 문제

### 백업 대기 중 계정 변경

워치에서 백업을 요청하고 아직 영수증을 받지 않은 상태에서 로그아웃하면 `isBusy`가 계속 true였다. 같은 계정으로 다시 로그인해도 새 백업을 할 수 없었다. 재현 테스트에서 버튼 대기 해제·메시지 초기화·새 요청 수가 모두 실패했다.

계정 ID가 바뀌면 화면의 활성 작업을 해제한다. 같은 계정의 닉네임 변경은 진행 중인 백업을 해제하지 않는다. 비동기 저장 전후에도 계정과 작업 ID를 확인하고 이전 작업의 실패로 새 작업을 해제하지 않는다. 이미 전송한 정상 백업 영수증은 유지해 로그아웃 뒤 늦게 도착해도 보상을 한 번만 적용한다. `64d08b8`.

### 전경 펫 갱신 수명과 활동 시각

초기 저장소 읽기가 늦은 상태에서 백그라운드로 나갔다 돌아오면 두 갱신 타이머가 생겼다. 초기 읽기 후 현재 활성 세대인지 확인하고, 중단된 타이머의 늦은 재개도 무시한다.

기존 10분 작업은 공복만 갱신해 `lastActiveAt`이 오래된 값으로 남았다. Android의 주기적 활동 시각 갱신처럼 전경 갱신 때 최근 활동도 기록한다. 두 회귀를 실제 파일 저장소·제어 가능한 시간으로 재현하고 수정했다. `d8ff29b`.

### 슈팅 콤보와 체력 0

Android 화면은 항상 현재 `COMBO!`를 표시하지만 워치 화면은 엔진에서 계산만 하고 표시하지 않았다. 점수·체력 아래에 현재 콤보를 표시하며 새 게임·피해·종료 시 엔진 상태를 반영한다.

복원 가능한 체력 0을 슈팅에서 임의로 1로 올리고 있었다. Android처럼 체력 0이면 0점으로 바로 종료하고, SpriteKit 장면도 즉시 결과를 전달한다. 공용 엔진과 워치 장면의 재시작 회귀로 확인했다. `01d1a74`.

## 자동 검증과 재실행

- 공용 **180개**, 워치 모델 **16개** 테스트 통과. 워치 모델은 백업 6개·활동 수명 2개·대화/랭킹/게임 종료 8개다.
- 수정된 Debug 테스트 빌드와 Release iOS/watchOS Simulator 빌드 통과.
- 네이티브 단계는 `Scripts/test_final_watch_audit.py`로 실행한다. 첫 5단계는 로그인 → 워치 먹이·반복 백업 → 워치 닉네임 변경 → 날짜 선택/복귀 → 윤년/연월 선택이다. 이어 기존 게임·랭킹·AI 13단계를 실행한다.
- 최종 네이티브 **18단계 모두 통과**했다. 각 결과 번들에서 실제 선택한 1개 검사 통과를 확인했으며, 아이폰·워치의 현재 저장 컨테이너에서 결과를 읽어 대조했다.
- 게임 보스·아이템·센서 기록의 날짜 경계·저장 실패·인증 만료 등은 공용/모델 테스트에서 검증한다. 실제 기기 성능·마이크 음성 인식·무선 환경·운영 Apple 로그인 및 운영 API 결과를 대신 검증한 것은 아니다.

```sh
swift test --package-path Packages/PetPetCore --scratch-path /private/tmp/petpet-daily-step-tests
python3 -B Scripts/test_final_watch_audit.py \
  --phone 96462AE4-4876-4635-A70E-EE0DBC2FCA05 \
  --watch 23172719-AC2C-4DAD-8FEB-8808093BD761 \
  --build /private/tmp/petpet-flow-build \
  --artifacts /private/tmp/petpet-final-new-run
```

전용 시뮬레이터 페어에서 두 앱을 먼저 설치·실행하고 피트니스 권한을 허용한다. 우유가 2개 이상 필요하며, 테스트는 한 개를 소비하고 두 번의 실제 모의 백업을 수행한다. 점수·걸음수·펫·자격 증명을 저장 파일에 주입하지 않는다. 각 단계에서 펫·먹이·백업 영수증·아이폰 캐시·모의 서버·닉네임을 대조한다. 결과 파일에는 인증 토큰을 포함하지 않는다.

첫 5단계에서 중단되면 같은 결과 디렉터리에 `--skip-build --from-stage N`을 사용한다. 게임 단계에서 중단되면 `Scripts/test_games_flow.py`에 결과 디렉터리의 `games` 경로와 `--skip-build --from-stage N`을 지정한다. XCTest는 실제 선택한 1개 검사 통과를 결과 번들에서 확인한다.
