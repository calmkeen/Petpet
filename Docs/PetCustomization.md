# 캐릭터·배경·동작 확장 구조

`develop`의 `33b9945`에서 분기한 `feature/pet-customization` 작업이다. 사용자가 종류는 미정이며 확장 구조부터 구현하도록 요청했다. 이번 범위는 기존 눈여우 1종과 기존 배경으로 선택·저장·동기화·동작 미리보기를 준비하는 것이다. 새 캐릭터 이미지를 임의로 만들거나 미보유 캐릭터를 선택지로 표시하지 않았다.

## 사용 경로

- 워치 메인 **상태 화면 → 펫 영역(붓 아이콘) → 꾸미기**.
- 캐릭터는 현재 눈여우 1종이다. 카탈로그에 캐릭터를 등록하면 같은 선택 목록에 추가된다.
- 홈 배경은 **시간대에 맞추기 / 새벽 / 낮 / 노을 / 밤** 중 선택한다. 고정 배경을 선택하면 시간대가 바뀌어도 유지한다. 홈과 상태 화면에 적용한다.
- **동작 미리보기**에서 쉬기·인사·달리기를 선택하고 다시 재생한다. 반복 클립은 미리보기에서 3초만 재생하고 단일 동작은 클립 길이만큼 재생한다. 화면 이탈·앱 비활성화·저휘도·동작 줄이기 설정에 맞춰 재생을 억제한다.
- 미리보기는 걸음수·쓰다듬기 횟수·애정도·능력치를 변경하지 않는다. 실제 홈의 걷기/쓰다듬기 반응은 기존 동작을 유지한다.
- 아이폰은 워치가 보낸 선택으로 펫 모습과 배경을 표시한다. 선택은 워치에서 수행하고 아이폰은 읽기 전용이다.

40mm 상태 페이지에 세 개의 액션 버튼을 나란히 추가하지 않았다. 기존 먹이·스탯 두 버튼을 유지하고, 기존 펫 영역을 꾸미기 진입점으로 사용한다. 실제 화면 배치 확인은 별도 시뮬레이터 검토 범위다.

## 모델과 저장

공용 `PetCustomization`은 `characterID`, `backgroundID`만 보관한다. 이는 **동일한 펫의 외형 선택**이며 새 펫을 생성하거나 독립적인 육성 슬롯으로 전환하지 않는다. API의 mate ID 1, 레벨·경험치·먹이·기록·보상과 대표 이미지 API는 변경하지 않는다.

선택은 워치의 환경별 `Application Support/PetPet/.../pet-customization-v1.json`에 저장한다. Debug와 Release 공간을 분리한다. 파일이 없으면 기존 눈여우와 시간대 자동 배경을 사용한다. 원자적 저장이 성공한 뒤 화면의 선택을 갱신하고, 저장 실패 시 기존 선택을 유지한다. 손상된 파일이나 지원하지 않는 버전은 조용히 덮어쓰지 않는다.

현재 선택은 워치 단위로 유지하며, 로그인 계정별 보유·해금·구매 기능은 포함하지 않는다. 서버 백업 DTO에는 새 필드를 넣지 않았으므로 앱 삭제·새 워치 이전 후 서버만으로 꾸미기 설정을 복원하는 기능은 이번 범위에 없다.

## 워치 → 아이폰 호환성

기존 `WatchSnapshot`에 선택적 `customization` 필드를 추가했다. 필드가 없는 이전 스냅샷도 읽으며 기본값으로 표시한다. 이전 아이폰은 알 수 없는 JSON 필드를 무시할 수 있도록 기존 버전을 유지한다.

워치가 선택을 저장하면 기존 revision 기반 발행 경로로 다시 전송한다. 꾸미기 파일 읽기에 실패해도 걸음수·펫 전송은 계속하며, 이미 발행했던 마지막 정상 선택이 있으면 함께 유지한다. 낯선 캐릭터/배경 ID는 원본 문자열을 보존하고 해당 기기에서는 기본 리소스로 표시한다. 수신한 ID를 파일 경로나 URL로 사용하지 않는다.

## 새 리소스 추가 방법

단일 등록 지점은 `Packages/PetPetCore/Sources/PetPetCore/Domain/Mate/PetCustomization.swift`의 `PetCustomizationCatalog`다.

1. 아이폰과 워치 양쪽 Asset Catalog에 같은 이름으로 이미지를 넣는다.
2. 캐릭터의 고유 ID·이름·기준 캔버스 크기와 `motions`를 등록한다. ID는 1~64바이트의 소문자 영문·숫자·하이픈으로 고정하고, 배포 후 재사용하지 않는다.
3. 기본 반응에는 `idle`, `greeting`, `running` 클립을 제공한다. `idle`을 첫 항목으로 둔다. 각 클립은 고유 ID·이름·순서가 있는 프레임·프레임 간격·반복 여부·정지 표시 프레임 인덱스를 정의한다.
4. 프레임은 최소 1장, 간격은 양의 유한 값, 정지 인덱스는 프레임 범위 안이어야 한다. 같은 캐릭터의 모든 프레임은 같은 투명 캔버스와 정렬·종횡비를 사용한다. 인사와 달리기에 16장을 강제하지 않는다.
5. 추가 동작을 `motions`에 등록하면 미리보기 목록에 자동으로 나타난다. 홈의 자동 이벤트에 새 동작을 배정하는 규칙은 해당 동작의 발동 조건을 정한 뒤 연결한다.
6. 새 배경은 고유 ID·이름·기호·`imageName`·`usesLightText`를 등록한다. 시간대 enum이나 화면의 분기문을 추가할 필요가 없다. `imageName == nil`인 항목은 시간대 자동 전환이다.

워치 렌더러는 선택된 캐릭터의 텍스처만 사전 로드한다. 캐릭터 전환 때 이전 로딩의 늦은 결과를 무시하며, 클립의 실제 프레임 수와 간격으로 보간한다. 아이폰 인사도 선택 캐릭터의 클립을 사용한다. 미니게임의 전용 플레이어 아트와 서버 대표 이미지는 별도 리소스·기능으로 유지한다.

## 검증 범위

사용자 요청에 따라 **빌드만 수행**하고 시뮬레이터 부팅·앱 실행·XCTest 실행은 하지 않는다.

- 공용 모듈과 테스트 타깃을 `swift build --build-tests`로 컴파일한다. 새 회귀 코드 6건은 파일 재열기·성장 데이터 보존·알 수 없는 ID·손상/새 버전 보호·이전 스냅샷·꾸미기 오류 중 정상 데이터 발행을 대상으로 작성했다. 실행 성공으로 계산하지 않는다.
- `PetPet` scheme의 Debug/Release generic iOS Simulator 빌드는 의존하는 워치 앱도 함께 빌드한다. 기존 캐시를 재사용하고 시뮬레이터는 시작하지 않는다.
- 별도 검토 때 40mm 진입점·배경 선택 후 복귀·재실행 유지·워치→아이폰 반영·각 동작 미리보기와 접근성 설정을 확인한다.

빌드 로그는 `/private/tmp/petpet-customization-core-build.log`, `/private/tmp/petpet-customization-build/`에 보관한다.
