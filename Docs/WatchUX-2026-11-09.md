# 40mm 워치 UI/UX 정리

## 변경 범위

- 홈: 펫과 걸음수를 나란히 배치하고 성장·먹이 버튼에 각각 44pt 이상의 터치 영역을 적용했다. 시간 표시 영역을 피하고, 밝은 배경에서도 버튼 글자가 보이도록 어두운 바탕을 사용한다. 걸음수 오류의 전체 설명과 재시도는 별도 안내창에서 확인한다.
- 섹션: 크라운으로 전환하는 짧은 개요는 유지한다. 세로 공간이 부족하면 보조 설명·이미지를 줄이고 주요 버튼과 핵심 상태를 남긴다. 긴 수치는 개요에서만 축약하며 상세와 VoiceOver는 원래 값을 유지한다.
- 성장·먹이·계정: 스크롤 가능한 기본 목록으로 정리했다. 능력치 `+` 버튼은 44×44pt로 키웠다. 능력치 이름과 값은 두 줄로 분리했다. 먹이기·보상·닉네임 등의 식별자와 동작 조건은 유지한다.
- 스트릭: 연·월 제목을 전체 너비로 배치하고 이전·다음 달을 별도 행으로 분리했다. 요일·범례의 10pt 고정 글자를 기본 캡션으로 바꾸고 범례 색상 칸은 가변 너비로 배치했다.
- 계정: 개요의 긴 닉네임은 가운데를 생략하며 VoiceOver에는 전체 이름을 제공한다. 닉네임 편집 화면에서는 전체 이름을 줄바꿈한다.
- 게임: 게임 선택과 랭킹을 구분하고, 게임 중 제목을 짧게 줄였다. 작은 안내 글자를 캡션으로 키웠다. 결과의 다시 하기와 랭킹 새로고침은 TOP 10보다 먼저 배치했다.
- AI 대화: 중단 버튼을 늘어나는 답변 앞에 배치했다. 목록에 버튼이 삽입된 다음 화면 중앙으로 이동해 전체 버튼을 바로 누를 수 있게 했다. 전송·계정·취소 처리는 기존 로직을 사용한다.

## 설계 기준

Apple은 짧게 확인하고 조작하는 화면, 크라운 활용, 작은 화면과 큰 글자 크기에서의 검증을 권장한다. watchOS의 기본 제어 크기는 44×44pt, 최소 크기는 28×28pt이다. 이 변경에서는 주요 사용자 버튼에 44pt를 적용하고 기본 내비게이션 도구막대는 시스템 크기를 사용한다.

- [Designing for watchOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos)
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

## 검증 결과

Xcode 27.2 (27B52)에서 Debug 테스트 빌드와 아이폰·워치 Release 시뮬레이터 빌드를 완료했다. 최초 SDK 교체·사용권 동의로 중단됐던 검증을 재개해, 최종 채택 실행에서 **XCTest 14종 모두 1건씩 성공, 실패·건너뛰기 0건**을 확인했다.

기본·큰 글자에서 주요 제어 영역의 위치·크기를 **40회 측정**했다. 펫은 64×64pt, 스탯 `+`는 44×44pt, 개요의 주요 버튼은 44pt 이상, 연월 선택 제목은 138pt 너비였다. 상세 목록은 크라운으로 스크롤하며 선택한 제어를 화면 안에 완전히 가져올 수 있는지 검사했다.

검증 환경은 전용 Apple Watch SE 2세대 40mm / watchOS 11.0과 iPhone SE 3세대 / iOS 18.0 페어다. 실제 기기는 사용하지 않았다. 모든 앱 캡처는 324×394px 워치 화면이며, XCTest 메타데이터의 `deviceName`이 아이폰으로 표시되는 경우에도 대상 워치 UDID와 캡처 크기를 함께 확인했다.

## 검사로 발견해 수정한 문제

1. 실제 타입 검사에서 걸음수 표시의 `Int` → `Int64` 변환 누락을 수정했다.
2. 홈의 오류 안내 버튼은 코드의 최소 프레임과 달리 실제 접근성 영역이 40.25×17pt로 측정됐다. 공통 버튼 스타일로 바꾼 뒤 74×44pt를 확인했다.
3. AI 대화에서 상태 글자만 대상으로 즉시 스크롤하면 중단 버튼 일부가 화면 아래에 남았다. 목록 삽입을 기다려 중단 버튼을 중앙에 배치하도록 바꿨다. 스크롤 없이 전체 버튼이 44pt 이상으로 보이는 검사를 통과했다.
4. 개요에서 작아 보이던 게임 그림을 키우고, 작은 화면에서도 먹이 그림을 유지하도록 조정했다. 기본·큰 글자로 개요 전체를 다시 검사했다.

## 테스트 설정과 데이터 보존

`--watch-ui-large-text`는 Debug에서만 `.xxxLarge`를 지정한다. Debug 실행 파일·분리된 debug dylib에 진입점이 존재하고 Release 바이너리에는 없는 것을 확인했다. 이 인자는 계정·저장 데이터·게임 규칙을 바꾸지 않는다.

Xcode 27의 크라운 입력은 완료 대기가 약 5초여서, 체력 9의 슈팅이 입력 검사 중 정상 종료되는 경우가 있었다. 슈팅 조작 검사 2건에 한해 **전용 시뮬레이터 저장 데이터의 체력을 9 → 99로 올리고 `finally`에서 9로 원복**했다. 게임 시계·피해·무작위 생성은 실제 코드 그대로 실행했다. 재설치로 데이터 컨테이너 경로가 바뀌는 경우도 현재 경로를 다시 조회해 복원한다. 앱에는 이 설정이 들어가지 않는다.

또한 시뮬레이터의 음성 입력 실패가 입력창을 닫지 못하는 경우를 처리하도록 XCTest에서 기본 손글씨 입력을 선택하고 입력창 종료를 기다린다. 제품의 입력 기능은 기존 시스템 UI를 사용한다.

검사 후 다음을 파일과 아이폰 수신 스냅샷으로 확인했다.

- 펫 레벨 2·경험치 2·공격 50·방어 0·체력 9·스탯 포인트 0 유지
- 우유 2개·사과 2개, 걸음 기록 3일 유지
- 기존 백업 ID 집합 5개·복원 ID 집합 1개 유지, 대기 백업 0개
- 아이폰 펫·먹이·걸음 스냅샷이 워치와 일치
- 테스트로 바꾼 닉네임 `FinalWatch217069`이 워치와 아이폰 모의 서버에서 일치

## 재실행

Debug 모의 계정으로 로그인된 위 전용 페어를 사용했다. 새 페어라면 아이폰의 개발용 계정 로그인을 먼저 완료해야 한다. 실행기는 두 대상이 시뮬레이터인지 확인하며, 각 실행 전 기존 성공 표시를 제거해 실패한 재검사에 이전 결과가 남지 않게 한다.

```sh
python3 -B Scripts/test_watch_ux.py \
  --phone 96462AE4-4876-4635-A70E-EE0DBC2FCA05 \
  --watch 23172719-AC2C-4DAD-8FEB-8808093BD761 \
  --build /private/tmp/petpet-watch-ux-272 \
  --artifacts /private/tmp/petpet-watch-ux
```

수정은 `4392741`(전체 배치), `32641e4`(최초 검사 준비), `f55144c`(걸음수·오류 안내), `b2001be`(중단 버튼), `4c1adea`(개요 그림·큰 글자 게임 검사)에 나눠 커밋했다.
