# 기능 공유 양식

새 기능 문서로 복사해서 작성한다. 모르는 값은 미정으로 두며, 코드가 있다는 이유만으로 합의·운영 확인 완료로 표시하지 않는다.

## 기준과 상태

- 기능 이름 / 작성일:
- 목적 / 사용자가 할 수 있는 일:
- 기준 develop 커밋:
- 구현 브랜치 / 커밋 / 접근 가능한 PR 링크:
- 다른 feature 의존성:
- 공통 규칙 상태: 제안 / 합의 / 반영
- iOS 상태: 계획 / 코드 구현 / 빌드 확인 / 모의 실행 확인 / 운영 확인
- Android 상태: 계획 / 코드 구현 / 빌드 확인 / 모의 실행 확인 / 운영 확인
- 서버 상태: 변경 불필요 / 계약 제안 / 구현 / 배포 / 연동 확인

## 동작 계약

- 진입점과 사용자 입력:
- 상태 전이·우선순위·취소 조건:
- 숫자 규칙·단위·상한·경계:
- 날짜·시간대·타이머 기준:
- 데이터 소유자: 워치 / 폰 / 서버
- 기존 성장·먹이·걸음수에 미치는 영향:
- 실패·중복 입력·재시작·오프라인 처리:
- 플랫폼별 허용할 차이:
- 이번에 포함하지 않는 것:

## 데이터·API·리소스

- 입력/출력 JSON 또는 상태 예시:
- 필드의 ID·기본값·선택 여부·미지원 값 처리:
- 로컬 저장 버전·기존 데이터 이관:
- 서버 API 변경과 호환성(기존 API / 새 제안 구분):
- 이미지·동작 ID·원본 위치·해시·프레임 순서·타이밍:
- 양쪽 구현 위치:

## 검증과 다음 작업

- 수행한 빌드·환경·결과:
- 실행한 테스트(없으면 0으로 표기):
- 수행하지 않은 검증:
- 별도 시뮬레이터 검토 항목:
- 남은 결정 / 다른 플랫폼·서버에 요청할 작업:
- 통합할 develop PR / 후속 작업 링크:
