# 선행 개발과 기능 인계

iOS에서 먼저 개발해도 Android가 소스 전체를 다시 분석하지 않고 같은 기능을 구현할 수 있도록 **규칙·예시 데이터·변경점·검증 상태**를 묶어 전달한다.

## 작업 순서

1. 최신 develop에서 독립 `feature/*`를 만든다. 다른 미통합 기능에 의존하면 그 의존성을 먼저 명시한다.
2. [기능 공유 양식](FeatureTemplate.md)에 사용자 동작, 숫자·날짜 규칙, 데이터 소유자와 미정 사항을 적는다.
3. 외부 서버에 새 계약이 필요 없으면 로컬 구조부터 선행 구현할 수 있다. 필요한 서버 변경은 **제안**으로 표시하고 기존 운영 API가 있다고 가정하지 않는다.
4. 코드와 함께 대표 입력→출력, 리소스 ID·프레임 정보, 이전 데이터 처리, 실패/취소 사례를 작성한다.
5. 기본 작업은 빌드까지만 확인해 커밋한다. 상태를 `코드 구현`, `빌드 확인`, `모의 실행 확인`, `운영 확인`으로 구분한다. 시뮬레이터 검토는 별도 요청에서 진행한다.
6. 공유할 브랜치를 원격에 올리고 PR을 만들 때 대상은 develop이다. PR·커밋·기능 문서·계약 변경을 묶어 전달한다. 로컬에만 있는 커밋을 접근 가능한 링크처럼 안내하지 않는다.
7. Android 개발자는 같은 예시 결과와 규칙을 기준으로 대응 코드를 구현한다. Kotlin 폴더 구조나 Swift 클래스 이름을 똑같이 만들 필요는 없다.

## 공유할 최소 묶음

| 내용 | 필요한 이유 |
|---|---|
| 기능 문서와 기준 브랜치·커밋 | 무엇을 가져가야 하는지, develop 포함 여부를 명확히 함 |
| 사용자 입력·상태 전이·수치 | 화면 이름만 같은 다른 동작을 방지 |
| 데이터 예시와 필드 의미 | ID·단위·날짜·기본값·누락 값 처리 일치 |
| API 변경 여부 | 클라이언트 구현과 서버 배포 상태를 구분 |
| 실패·중복·취소·재실행 사례 | 정상 동작 외의 결과도 같은 기준으로 구현 |
| 리소스 원본·이름·타이밍·해시 | 같은 캐릭터와 동작을 재현하고 원본 추적 가능 |
| 실제 수행한 검증 | 빌드만 한 작업을 실행 검증 완료로 전달하지 않음 |

## 선행 개발 예시: 캐릭터·배경·동작

### 현재 iOS 구현 상태

`feature/pet-customization`의 세 커밋 `01b38a7`, `3d3ea67`, `4fbf6b6`에 구현되어 있다. develop과 이번 별계단 브랜치에는 아직 합치지 않았다. Debug/Release 빌드는 확인했고 UI·워치→폰 실행 검토는 대기다.

현재 사용 가능한 캐릭터는 눈여우 **1종**이다. 새 동물이나 배경을 임의로 제작한 상태가 아니라, 리소스를 나중에 등록할 수 있는 구조다.

### 전달할 동작 규칙

- 선택은 동일한 펫의 **외형 변경**이다. 레벨·경험치·능력치·먹이·걸음수·보상을 초기화하지 않으며 서버 mate ID도 바꾸지 않는다. 캐릭터별 별도 육성은 구현하지 않았다.
- 배경은 `automatic`, `dawn`, `day`, `sunset`, `night`다. 고정 선택이면 시간대가 달라져도 같은 배경을 표시한다.
- 자동 배경은 기기 로컬 시각 기준 7시 새벽, 8~16시 낮, 17시 노을, 나머지 밤이다.
- 현재 동작은 `idle`, `greeting`, `running`이다. 홈은 새 걸음수 증가 시 달리고 2초 동안 증가가 없으면 쉰다. 저장된 누적값을 처음 읽은 것만으로 달리기를 시작하지 않는다.
- 유효한 펫 터치가 저장된 뒤 인사를 시작한다. 달리기·인사 중 중복 입력은 받지 않는다. 쓰다듬기 50회당 애정 +1 규칙은 그대로다.
- 동작 미리보기는 시각 표현만 바꾸며 애정·걸음수·게임 기록을 쓰지 않는다. 반복 동작 미리보기는 3초, 단일 동작은 클립 길이만큼 재생한다.
- 미정인 해금·상점·구매·캐릭터별 성장·서버 소유권 검증은 넣지 않았다. 양쪽에서 구현하기 전에 별도 규칙으로 정한다.

### 선택 데이터

```json
{
  "characterID": "snow-fox",
  "backgroundID": "night"
}
```

이것은 **로컬 선택/기기 간 표시 정보** 예시다. 현재 운영 서버의 새 요청 본문이나 엔드포인트가 아니다. 로컬 파일은 버전 1 문서 안에 이 선택을 저장하고, 워치 표시용 스냅샷에는 선택적 `customization`으로 넣는다.

| 계약 | 현재 규칙 |
|---|---|
| ID | 1~64바이트, 소문자 영문·숫자·하이픈. 표시 이름과 분리하고 배포 후 다른 항목에 재사용하지 않음 |
| 이전 데이터 | 선택 필드가 없으면 눈여우·자동 배경 |
| 모르는 ID | 원문을 보존하고 현재 기기에서는 기본 리소스로 표시. 파일 경로나 URL로 사용하지 않음 |
| 저장 실패 | 이전 선택 유지. 성장 데이터와 별도 파일 |
| 설정 파일 읽기 실패 | 걸음수·펫 동기화는 계속하고 마지막 정상 표시 설정을 유지 |
| 기기 간 소유권 | 워치에서 편집하고 폰은 받은 선택으로 표시 |
| 계정·백업 | 워치 단위 로컬 설정. 계정별 해금이나 서버 백업/복원은 포함하지 않음 |

### 리소스·동작 정의

캐릭터에는 고유 ID·표시 이름·기준 캔버스 크기와 동작 목록을 등록한다. 동작마다 ID·표시 이름·프레임 순서·프레임 간격·반복 여부·정지 표시 프레임을 둔다. 쉬기·인사·달리기의 기본 키는 유지하고, 추가 키는 양쪽에서 의미를 합의한다.

현재 눈여우의 인사/달리기는 16프레임, 프레임 간격 1/15초다. 인사는 한 번, 달리기는 반복한다. 새 캐릭터에도 16장을 강제하지 않는다. 모든 프레임의 투명 캔버스·정렬·종횡비를 맞춰야 한다. 배경은 이미지 이름과 밝은/어두운 글자 사용 여부를 함께 제공한다.

Apple 등록 지점은 해당 feature의 `PetCustomizationCatalog`이며 `PetSpriteAnimation`, `WatchPetRenderer`, `NativePhonePetSprite`가 재생한다. Android는 같은 ID·프레임·시간 규칙을 자체 리소스/렌더러에 연결하면 된다. 게임 전용 플레이어 아트와 서버 대표 이미지는 별도 기능이다.

### 양쪽이 확인할 예시

| 입력/상황 | 기대 결과 |
|---|---|
| 선택 파일 없는 기존 설치 | 기존 펫·기록을 유지하고 눈여우/자동 배경 |
| 밤을 선택한 뒤 낮이 됨 | 밤 배경 유지 |
| 자동을 선택한 뒤 17시→18시 | 노을→밤 |
| 외형 선택·앱 재실행 | 선택 유지, 성장·먹이 변화 없음 |
| 알 수 없는 캐릭터 ID 수신 | 다른 기록 수신을 막지 않고 기본 외형 표시 |
| 동작 미리보기 10회 | 터치 횟수·애정도·걸음수 변화 없음 |
| 저장된 큰 걸음수를 처음 읽음 | 달리기 시작 안 함. 이후 실제 증가를 받으면 시작 |
| 앱 비활성화·저휘도·동작 줄이기 | 네이티브 설정에 맞춰 재생 억제 |

## 이번 별계단 기능 인계

- 정답이면 **입력한 방향**의 원본 1번 프레임을 80ms, 2번을 100ms 보여준 뒤 기본 자세로 돌아온다. 다음 계단 방향을 사용하지 않는다.
- 빠른 다음 입력이 오면 이전 반응을 취소한다. 이전 작업이 늦게 끝나 새 반응을 기본 자세로 덮어쓰지 않도록 한다.
- 오답·타이머 시간 초과는 각각 실패 피드백 1회다. 마지막 목숨의 시간 초과도 포함하며, 타이머와 입력 직전 시간 검사에서 중복 소비·진동하지 않는다.
- 수동 종료는 실패 진동을 만들지 않는다. 일시정지·재시작·화면 이탈·저휘도·동작 줄이기에서는 반응을 정리한다. 접근성의 동작 줄이기는 정답 애니메이션을 억제하고 실패 이벤트의 의미는 유지한다.
- 원본 프레임과 타이밍은 Android 고정 커밋에서 가져온다. [세부 변경·리소스·빌드 기록](../StarStairFeedback-2026-11-14.md).

## 다음 기능에서 먼저 정할 항목

캐릭터 목록·원본 이미지, 배경 목록, 새 동작의 발동 조건, 캐릭터별 성장 여부, 해금/보유 규칙, 서버 저장 필요 여부를 정한다. 선행 구현에서 가정한 내용을 정식 공통 규칙으로 오해하지 않도록 문서의 `제안/합의/반영` 상태를 갱신한다. Android·iOS 계정 병합은 현재 개발 범위에서 제외한다.
